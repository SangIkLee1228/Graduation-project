# 후속 실험 계획

상태: 두 Semantic ID 생성 파이프라인 통합 완료. 아래 메트릭과 프로토콜은 제안이며,
baseline 학습, 추천 성능 평가, 최종 방식 선택은 아직 수행하지 않았다.

## 1. 평가 데이터와 과제 확정

- 런던 중심부 g186338에 한정해 사용자별 상호작용 수와 시퀀스 길이를 먼저 집계한다.
  최소 3개 상호작용 사용자 수, 최소 5개 사용자 수, 남는 호텔 수를 보고한다.
- TripAdvisor 리뷰 작성 시각은 예약 시각이 아니다. 과제는 리뷰 이력 기반 다음 호텔 예측으로 정의한다.
- 모든 리뷰를 방문 신호로 쓸지, 특정 평점 이상만 선호 신호로 쓸지 결정한다.
- 기본 비교안은 사용자별 시간순 마지막 항목 test, 그 이전 항목 validation, 나머지 train이다.
  같은 날짜의 정렬, 반복 방문, 최소 이력 길이, cold-start 처리 규칙을 고정한다.
  기존 `scripts/preprocessing/08_make_views.py`는 전역 연도 분할(~2017/2018/2019)이므로 같은 프로토콜이 아니다.
- 개인별 분할은 사용자 간 전역 시간 경계를 보장하지 않는다. 현실적 배포 평가가 필요하면
  전역 cutoff를 적용한 별도 실험을 추가하고 결과를 구분한다.
- 현재 프로파일과 ID는 전체 기간 리뷰를 사용했을 수 있다. 생성 시점과 입력 리뷰를 확인하고,
  엄격한 시간 기반 평가에서는 학습 기간 리뷰만으로 프로파일·임베딩·ID를 다시 만든다.
  해당 시점의 카탈로그와 cold-start 처리도 명시한다.
- BM25의 사용자 query에는 예측 이전 이력만 넣는다. 정답 리뷰를 query에 사용하지 않는다.
- 공통 호텔 카탈로그, 후보 목록, 이미 방문한 호텔의 마스킹 정책을 모든 방식에 동일하게 적용한다.
  정답이 후보 목록에서 빠지는 사용자 수와 처리 규칙도 보고한다.

## 2. 추천 성능 메트릭 제안

주 메트릭은 **NDCG@10**, 함께 **Recall@5/10/20**과 **NDCG@5/20**을 보고한다.
단일 정답 next-item 평가에서 Recall@K와 Hit Rate@K는 같으므로 중복 지표로 강조하지 않는다.
전체 카탈로그 랭킹을 우선 사용하고, sampled-negative 평가는 별도 표로 분리한다.

| 지표 | 목적 |
|---|---|
| NDCG@K | 정답을 상위에 배치하는 정도 |
| Recall@K | 상위 K 안에 정답을 포함하는 정도 |
| MRR@10 (보조) | 첫 정답의 순위 |
| Catalog Coverage@10 (보조) | 추천된 서로 다른 호텔 / 후보 호텔 수 |
| 추론 시간, 학습 시간 | 정확도와 실행 비용 비교 |

동일 분할·seed 3개 이상으로 평균과 표준편차를 보고한다.
튜닝과 early stopping은 validation NDCG@10만 사용하고 test는 최종 평가에 사용한다.
RMSE/MAE는 평점 예측 과제를 별도로 수행할 때 사용한다.

## 3. Semantic ID 자체 평가

- C1~C3 충돌 그룹 수, 그룹 크기, C4 추가 후 고유성.
- 레벨별 코드 사용률, 사용 분포 및 entropy/perplexity.
- 같은 prefix의 호텔 간 cosine 유사도와 무작위 호텔 쌍의 유사도 비교.
- prefix 길이별 그룹 내 유사도, 원 임베딩의 가까운 이웃 보존율.
- K-means 잔차 오차와 RQ-VAE 검증셋 재구성 오차.
  서로 다른 임베딩·정규화 공간의 오차를 직접 비교하지 않는다.
- 최종 판단은 동일한 추천 모델에서 두 ID 방식의 NDCG/Recall 차이로 한다.
  임베딩 모델과 코드북 크기가 모두 달라 현재 비교는 전체 파이프라인 비교다.
  양자화 방식 자체의 효과를 보려면 임베딩 및 용량을 맞춘 ablation이 필요하다.

## 4. Baseline 조사 및 구현 순서

사용자가 언급한 bert2rec은 우선 BERT4Rec을 뜻하는 것으로 가정한다.

1. **MostPopular**: 학습 데이터의 방문 수 기준. 공통 evaluator 점검용.
2. **BM25**: 호텔 프로파일을 문서로 인덱싱하고, 과거 호텔 프로파일을 사용자 query로 구성한다.
   BM25는 신경망 학습 대신 인덱싱과 k1/b 등 파라미터 튜닝을 수행한다.
   query 길이 및 토큰화 규칙을 고정한다.
3. **SASRec**: 사용자별 호텔 ID 시퀀스로 다음 호텔을 예측하는 baseline.
4. **BERT4Rec**: 호텔 시퀀스의 masked-item 학습, 평가 시 마지막 위치의 다음 호텔 예측.
5. **Semantic ID 기반 모델 두 종류**: 같은 추천 모델·예산에 K-means ID와 RQ-VAE ID를 각각 연결.

초기 baseline SASRec/BERT4Rec은 일반 호텔 ID를 사용한다.
Semantic ID 생성만으로 추천 모델 학습이 완료되는 것은 아니다.
원 구현을 먼저 읽고 라이선스·의존성·평가 코드를 확인한 뒤 같은 실험 인터페이스에 연결한다.
기존 평가기의 negative sampling과 공통 전체 카탈로그 평가를 혼동하지 않는다.
